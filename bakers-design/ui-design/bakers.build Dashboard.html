Komponenten-Notizen · Twig · CSS · Gin · htmx · Felder

Eine Ebene — Filter im Querystring

Keine separate /my-Route mehr. Die Filterleiste (projects[], conductors[], mine, wf) schreibt in den Querystring; jedes Fragment liest dieselben Query-Parameter und filtert serverseitig. „Meine" = assignee_user_id == uid ODER conductor-owner ist der angemeldete Nutzer.

# Beispiel-State
?projects=bakers,intern&conductors=all
  &mine=1&wf=feature

Fragment-Wurzel = htmx-Einheit

Polling pro Sektion; der Querystring wird in jeden hx-get durchgereicht (hx-include="#filters"), damit Refresh den Filter behält. outerHTML-Swap, Polling pausiert bei verstecktem Tab.

<section class="sec" id="frag-active"
  hx-get="/admin/bakers/frag/active"
  hx-include="#filters"
  hx-trigger="every 15s [
    document.visibilityState==='visible'],
    change from:#filters"
  hx-swap="outerHTML"
  hx-sync="this:replace"> … </section>

Aktive Tickets — Sortierung & Status

Board-unabhängig: alle Tickets, deren state nicht backlog/done/cancelled ist. Eine Zeile, ein data-st. Sortierschlüssel absteigend nach Dringlichkeit, dann nach Alter:

  • wait — run.state=needs_input & kein Assignee (rot)
  • needs_input — run.state=needs_input, zugewiesen
  • attention — run.attention gesetzt
  • running — run.state=running
  • idle — kein aktiver Run (zuletzt)

Board — workflow-bestimmt

Ein Tab pro Workflow; die Spalten sind nicht hartkodiert, sondern die states des jeweiligen Workflows in Reihenfolge. Leere & übersprungene States (bug ohne spec, chore ohne spec+review) erscheinen gar nicht — die Workflow-Form bleibt lesbar.

{% for state in workflow.states %}
  <div class="col" data-col="{{ state.id }}">
    {{ column(state) }}
  </div>
{% endfor %}

Gin-Variablen (wiederverwendet)

Keine Neutralfarbe hartkodiert — Gins Tokens werden konsumiert, dadurch laufen Light/Dark & Accent-Color automatisch durch:

  • --gin-app, --gin-layer, --gin-layer-2/3
  • --gin-line-color, --gin-color-text(-light)
  • --gin-color-primary (Links, aktive Tabs, Fokusring)
  • --gin-line-radius, --gin-spacing-*, --font-sans-family

Polling-Feedback — kein Flackern

Statt Ausblenden: während des Requests Inhalt auf opacity:.55 dimmen, nach Settle zurück (120 ms, kein Layout-Shift). Der Ring oben zählt die 15 s sichtbar herunter.

htmx.on('htmx:beforeRequest', e =>
  e.target.dataset.refreshing = '1');
htmx.on('htmx:afterSettle', e =>
  delete e.target.dataset.refreshing);

Echte Feldnamen (für Twig)

// bb_ticket
identifier · title · state · assignee_user_id · project_id

// bb_run
state          // claimed | running | retrying | released | succeeded | failed | needs_input
claim_owner    // Maschinen-String, z. B. "cw-laptop-bakers"
attention      // Timestamp; gesetzt = Agent wartet im Terminal
claim_expires_at // Lease-Countdown

// bb_conductor
machine_id · states · current_load · max_parallel · last_seen
// Aktiv-Ampel: now() - last_seen < 600s ⇒ ● online, sonst ○ stale

bakers.build-Zustands-Tokens (das Einzige, was bakers.build an Farbe einbringt)

Vier semantische Tokens, geseedet aus dem keytec-Palette, mit Fallback auf Gins Status-Farben. Codierung immer doppelt — linke 3 px Akzentkante (Zeile/Karte) + Statuspunkt/Pille — nie Farbe allein. Keine Emoji; attention/needs_input sind als SVG gezeichnet.

:root {
  --bakers-unassigned: #FF4E42;  /* swimsuit — needs_input ohne Assignee = kritisch (rot) */
  --bakers-attention:  #FFC024;  /* sun      — needs_input zugewiesen · attention · stale (amber) */
  --bakers-running:    #4BB9AE;  /* teal     — Run läuft · Node online (grün) */
  --bakers-lease:      #8197F8;  /* ocean-tint — aktive Lease / Claim-Besitz (neutral, kein Alarm) */
}
