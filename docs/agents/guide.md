# Configure and select agents

Configuration defines the agents available on a machine. Selection chooses which of them runs a ticket: either one agent from the catalog or a route that selects agents by workflow state.

- [Configure agents](#configure-agents): choose a setup below and see the complete machine file.
- [Select an agent](#select-an-agent): use the configured default, an alias label or a route label.

<span id="choose-agents-and-models"></span>
<span id="understand-the-choices"></span>

In bakers.build, **harnesses are addons**. A harness addon supplies **agent plugins** that run a coding program such as Claude Code or Codex. Configure a plugin's model and options, then give that configuration an **alias**. The **catalog** is the set of available aliased configurations; a **route** selects from that catalog.

Both setups live in `~/.bakers/machine.config.js` on the execution machine. [Configuration → Machine → Agents](/configuration/machine#agents) explains how these settings fit the machine file and links the detailed field and precedence references.

**You need:** bakers.build signed in, a connected project checkout, and the harness program installed, on `PATH` and authenticated as the conductor user. Follow the [harness addon instructions](/agents/reference#harnesses); enabling an addon does not install or sign in to the program.

**Keep your existing machine identity and settings.** The examples below show complete files with a sample identity. Keep the real `machine_id` generated by `bakers init`, your label, and existing addons and settings. Merge the shown `agents` fields into your existing object; do not create a second `agents` key. Keep the machine file private and out of Git.

### Use one agent

If the catalog already contains the agent you want, select its alias directly. A custom catalog entry is optional. This complete example enables the [Claude addon](/addons/claude), adds a Sonnet configuration named `coder`, and makes it the default:

```js
// @bakers-schema-version 1
export default {
  schema_version: 1,
  machine_id: '0b6f3c1e-9a2d-4e57-8c41-2f7d9e5a1b30', // Keep your existing ID.
  label: 'alex-laptop',
  addons: ['@bakers-build/addon-claude'],
  agents: {
    catalog: [
      {
        harness: '@bakers-build/addon-claude',
        alias: 'coder',
        with: { model: 'sonnet' },
      },
    ],
    routes: {
      default: { '*': 'coder' },
    },
  },
};
```

`addons` enables the harness. `agents.catalog` configures its agent plugin: `harness` identifies the addon, `with` supplies options, and `alias` names the resulting configuration. `coder` is added alongside the addon's built-in aliases, including `opus`; reusing an alias replaces its configuration.

The `default` route selects an alias from that catalog for every state (`'*'`). With this file and no ticket selector, runs use `coder`. Without a `default` route, the first enabled alias is the default. Continue to [selection](#select-an-agent), or read the [catalog and filter details in Configuration](/configuration/machine#the-agents-object).

### Use agent routes

Use routes when different workflow states need different agents. This alternative complete file keeps the same catalog and adds a named route to `agents.routes` **alongside** `catalog` and the `default` route:

```js
// @bakers-schema-version 1
export default {
  schema_version: 1,
  machine_id: '0b6f3c1e-9a2d-4e57-8c41-2f7d9e5a1b30', // Keep your existing ID.
  label: 'alex-laptop',
  addons: ['@bakers-build/addon-claude'],
  agents: {
    catalog: [
      {
        harness: '@bakers-build/addon-claude',
        alias: 'coder',
        with: { model: 'sonnet' },
      },
    ],
    routes: {
      default: { '*': 'coder' },
      reviewed: {
        working: 'coder',
        review: 'opus',
        '*': 'coder',
      },
    },
  },
};
```

`reviewed` is the route name. Its keys are workflow states, its values are catalog aliases, and `'*'` covers other states. Both `coder` and `opus` are available from this file. Choose a route name that is not also an alias.

Defining `reviewed` makes it available; [select it with a ticket label](#select-an-agent). Until selected, this file still defaults to `coder`. The special `default` route is the one applied without a ticket label; see [selection and routing in Configuration](/configuration/machine#which-agent-runs-a-state).

Routes select existing agents; they neither choose a conductor nor move the ticket through its [workflow](/skills-and-workflows/states). Make the catalog and route available on every execution machine that may run the ticket.

### Inspect the catalog

In the connected project checkout, run:

```sh
bakers agents
```

Check that `coder` uses the Claude harness with model `sonnet`. For the route setup, also check `opus` and `routes.reviewed`. If you use allow/deny filters, they must retain those aliases. This command neither installs a harness nor checks its login; `bakers config check --scope machine` does not validate the agent catalog.

## Select an agent

Selection uses what you configured; it does not change a plugin's model or options.

<span id="set-the-machine-default"></span>
<span id="select-an-alias-on-a-ticket"></span>

| What you want | Ticket selection | Result with the examples above |
|---|---|---|
| Use the machine default | No `agent:` label | The `default` route applies: `coder`. |
| Use one catalog entry | `agent:coder` or `agent:opus` | That alias runs in every state. |
| Use the configured route | `agent:reviewed` | `coder` in working, `opus` in review, `coder` otherwise. Requires the route setup. |

Add the chosen label through the ticket's normal label editing. Use either an alias or a route label: a direct alias takes precedence if both are present. A state-specific label such as `agent:opus@review` applies only in that state.

These results assume the shown files and no other selectors. On an existing machine, a `default` route that maps states other than `'*'`, custom selectors and state-specific labels can also change the result. See [Configuration's selection reference](/configuration/machine#which-agent-runs-a-state) for the complete order.

### Verify the run

Run a small ticket and inspect the recorded agent and model. With `agent:coder`, expect Claude/Sonnet. With `agent:reviewed`, check both working and review. Unknown or unavailable labels can warn and fall back, so a label alone is not proof.

**Done when:** the catalog contains your intended configurations and the runs record the agent and model selected for each checked state.

## When loading fails

If `bakers agents` fails, check the named addon, alias or filter in its error. At least one agent must remain available, and the `default` route's `'*'` alias must name one. [Machine verification](/configuration/machine#verify) and the [agent reference](/agents/reference#old-keys-and-verification) explain the checks and retired keys.

## Required and optional values

A harness addon and an available agent are required. Custom aliases, filters and routes are optional. [Configuration → Machine](/configuration/machine) owns file location, identity and other machine settings; [Agent policy](/agents/reference) lists every agent field and precedence rule.

[Skills](/skills-and-workflows/skills) supply instructions, the [executor](/addons/slots) hosts the session, the [client](/get-started/use-your-client) is how you interact with the work, and the [worktree environment](/provision/guide) runs the application. Review [execution security](/provision/security/execution) before extending access.
