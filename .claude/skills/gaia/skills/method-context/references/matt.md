# Matt skill set

> **Pick for hard, under-specified problems.** At spec it grills you to a shared understanding
> (`grilling`), then synthesizes that into the spec on the ticket (`to-spec`) — plus test-first
> (`tdd`) and code-review discipline. Best when the shape of the work is still unclear and needs
> pinning down before a plan exists.

Agent calibre: prefer a strong reasoner and implementer that can resolve ambiguity, challenge
assumptions, and sustain test-first work without a fully prescribed implementation.

Use the original skills from `mattpocock/skills`, as made available by the agent's environment.
Names below identify upstream skills, not installation paths or a GAIA-managed package.
Use this collection under the loading and ticket-context contract in `@gaia/method-context`.

| Work step or condition | Skill |
|---|---|
| Specification and implementation plan | `grilling`, then `to-spec` |
| Diagnosis | `diagnosing-bugs` |
| Coding | `implement` |
| Test-first work at agreed seams | `tdd` |
| Review | `code-review` |
| Writing reusable agent instructions | `writing-for-agents` |

Apply conditional rows only when they fit the task. GAIA lifecycle steps without an engineering
method use their existing owner. A method's activity beyond the current GAIA state waits for that
state; for example, coding hands review context to the review state.
